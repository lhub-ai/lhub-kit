# deal-artifact v1 · cross-language test vector `vector-v1`

**Provenance.** These three files are the FROZEN cross-language canonicalisation
contract for `dealartifact` v1. They were AUTHORED BY HAND per RFC 8785 rules —
NOT generated by this package's own `Canonicalize` — so the byte-equality tests
that consume them (Go: `TestBuild_MatchesFrozenGoldenFixture`; Python: the
mirror in the house-agent's `dealartifact` builder tests) cannot silently pass
if canonicalisation drifts on either side. That is what makes the D-8
"additive extension, not a version bump" promise a CHECKABLE property (see
`../../dealartifact.go` package doc) rather than an intention.

**Files.**

- `input.json` — human-readable content, encoded as an unsorted JSON object.
  The single fixture consumed by both language implementations. Fields are the
  D-6 v1 field set with realistic placeholder values (`did:example:*` DIDs, a
  zeroed listing content hash, `amount = 100000` minor units well below
  `MaxAmount`).
- `canonical` — the RFC 8785 (JCS) canonical bytes the content in `input.json`
  MUST canonicalise to. 349 bytes, NO trailing newline. Applying RFC 8785 by
  hand: keys sorted alphabetically (`amount` … `version` — for ASCII this is
  UTF-16 code unit order too), no whitespace between tokens, no `\uNNNN`
  escapes needed (the placeholder strings have no metacharacters), integer
  `amount` emitted without a decimal point.
- `content_hash` — the lower-case hex SHA-256 of `canonical`, 64 chars, NO
  trailing newline. Cross-checked against `shasum -a 256 canonical` (see the
  handover); a second, independent tool that agrees on the hash is the
  external ground truth this file freezes.

**Reproducing the freeze locally.**

```sh
# byte length + hash agreement
wc -c testdata/vector-v1/canonical              # -> 349
shasum -a 256 testdata/vector-v1/canonical      # -> matches content_hash

# hand-verify RFC 8785 keys are alphabetically sorted (should print sorted list)
python3 -c 'import json; d=json.load(open("testdata/vector-v1/input.json")); print(sorted(d.keys()))'
```

**Do NOT regenerate these files from `dealartifact.Build`.** The whole point
of the frozen fixture is that `Build`'s output is compared AGAINST them; a
regeneration-from-the-implementation loop would silently accept any future
canonicalisation change. If the shared `signing.Canonicalize` primitive is
ever intentionally changed in a way that alters these bytes, the change is
a NEW major schema version (a new `deal-artifact.v2.schema.json` and a new
vector directory), not a re-freeze.
